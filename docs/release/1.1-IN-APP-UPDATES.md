# WiiDS 1.1: in-app updates

The current 1.1 APK adds **Options → Check for updates**. It reads the latest public WiiDS GitHub release, downloads the APK inside WiiDS, and opens Android's installer to update your existing app. You do not need to open a browser for future updates.

1. Close any running game and finish any game import or save operation.
2. Open **Options → Check for updates**, then choose **Download update** when one is available.
3. You can leave this screen while Android downloads the update. Return here to see progress or cancel it.
4. Choose **Install update**. If Android asks, allow WiiDS to install apps from this source, then return to WiiDS.
5. Confirm Android's update prompt and reopen WiiDS. Open **Check for updates** once more to clear the completed download and confirm you are up to date.

Install over your existing WiiDS copy. **Do not uninstall or clear app data.** Imported games and saves remain in place. The updater checks available storage before downloading; the current full APK needs about 3.7 GiB of free space for downloading and installation. It does not download a small incremental patch.

## Getting this first updater build

Older copies do not have this menu yet. Download the current [WiiDS 1.1 APK](https://github.com/Maddex712/WiiDS/releases/download/v1.1.0/WiiDS-1.1-arm64.apk) once and install it over your existing copy. Future releases can then be checked from inside WiiDS.

The public version remains **1.1**, on the existing `v1.1.0` release page. Its internal Android build code is **1102**. The updater compares internal build codes, so it can recognize replacement builds published under the same public version without weakening verification.

## Verification and limits

The updater accepts the stable release from `Maddex712/WiiDS`, checks GitHub's SHA-256 metadata and the release inventory, and verifies the downloaded APK's full checksum, package, version, build code, and signing certificate before committing an Android installer session. Android requires the user's installation confirmation. Older or mismatched builds are refused.

Downloads are managed by Android and continue after leaving the update screen. Installation is blocked while a game, import, or save operation is active. Cancellation keeps the current app installed. A network or storage failure can be cancelled and retried from this screen. GitHub rate limits may temporarily prevent update checks.

This update retains the Kaizo cover, disc and spine hotfix. All 25 native libraries and 1,477 game/menu/presentation assets match the preceding 1.1 artwork hotfix. Only the Android frontend and release metadata changed. The existing gameplay testing limits still apply.
