# WiiDS 1.1 source profile

The current local candidate uses the dev28 source profile with release version
`1.1` and code `1100`. It includes the bundled-asset installer correction,
all-eight-profile Dolphin import adapters, Galaxy Picture choices, relative
Trackpad input, native camera restrictions, material animations and attack colors,
material/ambient and point-light corrections, timed
hint, single-tap menu, retained kart shortcut routing and MSMBWii lower title.
The candidate is local; no commit, push or publication is part of this review.

Compared with the accepted dev15 APK, 24 native libraries and all 1474 game/menu
assets are identical. Galaxy's changed `libgame.so` is pinned by a native receipt
that starts from exact dev17 and carries its five Picture changes forward with
all subsequent control/lighting source hashes. Candidate packaging checks every
native/asset delta, signature, version and nondebuggable status.

## Achievement-preserving source selection

The ordinary workbench retains a separate paused earning-client experiment.
`experiments/release/export_1_1_source.py` applies this profile only while reading:

1. Verify all 91 recorded experiment files against their retained hashes.
2. Restore the recorded pre-experiment bytes for 13 modified files and omit 78
   additions. This includes NSMB VI, CMake and disc-interface sources. Workbench
   files remain untouched.
3. Verify Android Java/Kotlin and the manifest against the private preview build;
   the 12 achievement restorations match the recorded dev7 baseline.
4. Include current NSMB/MSMB overlay/frame guards, crash diagnostics, save manager,
   Dolphin adapters, shortcuts, motion, achievement library and Galaxy changes.
5. Retain the standard source-coverage, component-pin, private-file, secret and
   curated-presentation checks.

The archive's `SOURCE-MANIFEST.json` hashes every included file. The separate
`source-profile.json` records substitutions and omissions. Build native targets
from the restored archive source; workbench-only helper paths into private
backups are not required for the normal build. Supply supported owner discs and
generate translations as documented in `README-SOURCE.md`. Private disc data,
owner saves and account credentials are not included.

## Artifacts and limits

Use `build/release-1.1-candidate5/candidate.json` and its matching source archive.
Earlier candidate through
candidate4 artifacts are historical and superseded. The dev28 production
library contains no temporary GPU/material capture logging. Native allocation
failures now record their request and bounded backtrace for diagnosis.
The device development build stays at code906 to retain normal preview-update
compatibility. The code1100 APK is prepared locally, not installed or published.

The source archive is inspectable and readback-verified. No clean-machine rebuild
is claimed. Keep component licenses and generation/build instructions with any
release. Device scope and outstanding rendering limits are documented in
[the game review](1.1-GAME-REVIEW.md).
